# 02. IC / 교차로 설계 지침 모니터링 어시스턴트 (IC Design Assistant)

고속도로 IC 연결로, 변속차로(Taper), 신호교차로 산정 공식 및 도로용량편람 등 교통·도로공학 기술 지침을 파싱하여 정밀한 규격 및 공식을 조회해 주는 AI 기술 어시스턴트입니다.

---

## 📌 주요 특징 (Key Features)

1. **지침서/표/수식 데이터 파싱 및 FAISS Vector DB 구축**
   - `data/` 폴더 내 도로용량편람 및 설계지침 PDF 문서를 자동 탐색하여 텍스트 및 기준표 임베딩.
2. **치수 및 공식 기반 정밀 답변**
   - Taper 비율, 설계속도별 최소 길이, 황색신호시간(Yellow Time) 산정 공식 등 기술 수치에 특화된 답변 출력.
3. **Gradio UI 기반 동적 RAG 파라미터 조절**
   - `gr.Slider`를 활용해 청크 크기(`chunk_size`) 및 검색 문서 수(`search_k`)를 웹상에서 실시간으로 조정하며 테스트 가능.

---

## 🎯 1. 프로젝트 목적 (Purpose)

1. **도로 및 교차로 설계 수식/수치 규격의 정밀 조회**
   - 변속차로 테이퍼(Taper) 비율, 설계속도별 최소 길이, 수직여유고 등 지침서 내 수치 데이터 자동 추출.
2. **동적 RAG 파라미터 조절 환경 구현**
   - 문서 특성에 따라 청크 크기(`chunk_size`)와 검색 문서 수(`search_k`)를 웹상에서 자유롭게 조절하며 최적의 검색 성능 도출.
3. **도로공학 기술 지침 조회 자동화**
   - 도로용량편람(HCM) 및 입체교차 설계지침 탐색 시간을 단축하여 엔지니어링 실무 생산성 향상.

---

## 💡 2. 추진 배경 (Why)

1. **교통시설 설계 지침 내 복잡한 수식과 기준표 참조의 불편함**
   - 도로 설계 시 속도, 설계기준자동차, 교차로 형태에 따라 적용되는 수식과 기준표가 분산되어 있어 조회에 시간이 많이 소요됨.
2. **단순 키워드 RAG의 한계 및 청크 분할 크기 영향성**
   - 수식이나 수치 표는 청크 크기가 작으면 문맥이 끊겨 왜곡되고, 너무 크면 정밀도가 떨어지므로 실시간 파라미터 조절 도구 필요.
3. **교통 기사 및 설계 실무자의 검토 가이드라인 표준화**
   - 신호 교차로 황색신호시간(Yellow Time) 산정 등 규격 계산 공식의 오적용을 방지하기 위한 전문 어시스턴트 절실.

---

## ⚠️ 3. 문제점 (Problems Addressed)

1. **설계 지침 수식 파싱 시 문맥 단절 현상**
   - PDF 내 표(Table)나 분수/곱셈 형태의 공식이 분할 과정에서 깨져 잘못된 수치를 답변하는 위험 존재.
2. **고정된 Chunk Size로 인한 검색 품질 저하**
   - 문서 유형별로 최적의 Chunk Size가 다름에도 단일 고정 값 적용 시 지침 검색의 정밀도 저하.
3. **설계 기준 근거 조항 제시 부족**
   - 산출된 최소 길이나 수치 규격에 대해 몇 페이지 지침을 참고했는지 명시하지 않을 경우 설계 도면 검토 시 재검증 필요.

---

## 🛠️ 4. 개선안 (Solutions Provided)

1. **Gradio Slider 연동 동적 RAG 파라미터 제어**
   - `gr.Slider`를 활용해 `chunk_size`(300~1500) 및 `search_k`(1~10)를 실시간 변경하여 최적의 RAG 인덱스 재구성.
2. **수식·수치 데이터 정밀 인용 프롬프트 설계**
   - 테이퍼 비율, 수직여유고, 곡선반경 공식을 명확한 단위(m, 초 등)와 함께 기재하도록 프롬프트 수칙 강화.
3. **참고 출처 페이지 매핑 및 대화 세션 유지**
   - 답변 출력 시 근거 페이지를 명확히 출력하고, 세션 내에서 연속 질문이 가능하도록 Gradio State 구축.

---

## 🚨 5. 한계점 (Limitations)

1. **복잡한 수식 이미지/도면 파싱 한계**
   - PDF 내 텍스트가 아닌 수식 이미지나 CAD 도면 레이어는 OCR 전처리 없이는 정밀 계산 불가.
2. **실시간 파라미터 변경 시 재인덱싱 소요 시간**
   - 청크 크기 슬라이더 조정 시 FAISS Vector DB를 재구축하므로 대용량 문서의 경우 수 초의 대기시간 발생.
3. **지자체별 도로 구조 세부 조례와의 상충 판별 미비**
   - 국토교통부 표준 편람 중심 검토로 각 지자체별 세부 도로점용 기준과의 세부 상충 검토는 보완 필요.

---

## 🛠️ 6. 실행 스크립트 이원화 설계 (Architecture)

본 프로젝트는 백엔드 수식/표 파싱 검증과 웹 UI 시연 환경의 유지보수성을 극대화하기 위해 **관심사 분리(Separation of Concerns)** 원칙에 따라 스크립트를 분리하여 구축했습니다.

| 구분 | `main.py` (CLI 백엔드 검증) | `app.py` (Gradio 웹 UI) |
| :--- | :--- | :--- |
| **핵심 역할** | RAG 파이프라인 및 수식 파싱 검증 | `gr.Slider` 기반 동적 RAG 파라미터 조절 및 대화형 QA |
| **주요 기능** | - 단일로 테이퍼, 수직 여유고 파싱 검증<br>- CLI상에서 빠른 파이프라인 결과 조회 | - `chunk_size` 및 `search_k` 동적 조절<br>- 출처 페이지 매핑 및 대화 세션 유지 (`Port 7862`) |
| **추천 활용** | 로직 수정, 프로토타이핑, 디버깅 | 포트폴리오 시연, 발표, 실무자 웹 구동 |
