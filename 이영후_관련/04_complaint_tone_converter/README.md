# 04. 도시교통 및 민원 대응 업무 말투 변환기 (Complaint Tone Converter)

시민 민원, 현장 비공식 메모, 일상적 어조의 요구사항을 지자체 및 공공기관 제출용 정형화된 행정 보고서체(개조식)로 자동 변환하는 LLM 파이프라인입니다.

---

## 📌 주요 특징 (Key Features)

1. **행정 개조식 문장 자동 변환**
   - 감정적·주관적 문장을 완벽히 배제하고 '민원 요약 / 주요 요구사항 / 현장 검토 필요 항목' 형태의 객관적 보고서체로 정돈.
2. **교통·행정 전문 용어 적용**
   - 상충, 지체, 병목, TOD 신호 재산정, 딜레마존 등 정밀한 전문 용어로 리라이팅(Re-writing).
3. **ChatInterface 및 실시간 피드백(Flagging) 수집**
   - `gr.ChatInterface`를 활용한 직관적 챗봇 인터페이스와 `Like/Dislike` 버튼으로 변환 품질 평가 데이터 모니터링.

---

## 🎯 1. 프로젝트 목적 (Purpose)

1. **거친 시민 민원 메모의 정형화된 행정 보고서체 자동 변환**
   - 감정적·주관적 표현을 배제하고 사실 관계 중심의 개조식 행정 보고서 형태로 리라이팅(Re-writing).
2. **교통 전문 용어 교정 및 표준화**
   - '길이 막힌다', '위험하다' 등 일반적 표현을 '지체', '상충', 'TOD 신호 재산정', '딜레마존' 등 전문 학술 용어로 정돈.
3. **변환 품질에 대한 실시간 피드백(Flagging) 데이터 수집**
   - `ChatInterface` 내 피드백 버튼을 통해 사용자의 변환 만족도 데이터를 수집하여 프롬프트 지속 개선 도구로 활용.

---

## 💡 2. 추진 배경 (Why)

1. **지자체 교통 담당자의 감정 노동 및 보고서 작성 업무 부담**
   - 전화 녹취나 구두로 접수된 거친 민원 텍스트를 보고서 형태로 재작성하는 데 과도한 시간 소요.
2. **비공식 현장 메모의 문서화 수준 미흡**
   - 순찰 직원의 비공식 메모나 시민들의 격앙된 요구사항이 그대로 보고서에 반영되어 행정 신뢰도 저하.
3. **민원 답변 변환 품질에 대한 정량적 수집 체계 부재**
   - AI가 변환한 문장의 행정 적합성을 사용자가 즉시 평가할 수 있는 피드백 루프 필요성 대두.

---

## ⚠️ 3. 문제점 (Problems Addressed)

1. **민원 텍스트 내 감정적 표현 포함으로 인한 공문서 적합성 결여**
   - "당장 고쳐요", "난리도 아님" 등 주관적 감정이 섞인 문장으로 인해 내부 결재 보고서 활용 불가능.
2. **주요 요약/요구사항/검토항목의 구분 없는 나열**
   - 문장 구조가 정리되지 않아 민원인의 실제 핵심 요구사항(신호 주기 연장 등)을 한눈에 파악하기 어려움.
3. **단순 요약으로 인한 주요 요구사항 누락 위험**
   - 일반 요약 모델 사용 시 민원인이 요구한 세부 현장 조치 내용이 왜곡되거나 생략되는 현상 발생.

---

## 🛠️ 4. 개선안 (Solutions Provided)

1. **3단계 행정 개조식 템플릿 프롬프트 강제화**
   - [민원 요약], [주요 요구사항], [현장 검토 필요 항목]의 3개 핵심 구문으로 나누어 개조식(- ) 작성 규칙 적용.
2. **Gradio ChatInterface 및 Flagging 옵션 연동**
   - `gr.ChatInterface` 기반으로 사용하기 쉬운 챗봇 UI를 제공하고 `Like`, `Dislike`, `표현 미흡` 버튼으로 피드백을 파일에 자동 저장.
3. **교통 행정 전문가 롤플레잉 적용**
   - Upstage Solar-Pro 모델을 활용하여 교통 분야 정밀 전문 용어로 문맥을 재구성하도록 리라이팅 파이프라인 연동.

---

## 🚨 5. 한계점 (Limitations)

1. **음성 녹취록의 OCR/STT 텍스트 변환 오차에 따른 왜곡 가능성**
   - 음성 인식(STT) 과정에서 교차로 명칭(예: 옥녀교차로 -> 옥년교차로 등)이 오기 입력된 경우 잘못된 명칭 그대로 변환될 수 있음.
2. **민원인의 복합/다중 요구에 대한 자동 우선순위 산정 한계**
   - 한 민원에 신호, 보행자 도로, 주차 단속 등 수개의 과업이 섞여 있을 때 우선순위 자동 판별은 프롬프트 상 한계 존재.
3. **공식 행정 공문서 자동 발송 시스템과의 미연동**
   - 본 시스템은 보고서체 변환 및 피드백 수집 목적이며, 전자결재나 온나라 시스템과의 direct API 연동은 미포함.

## 🛠️ 6. 실행 스크립트 이원화 설계 (Architecture)

본 프로젝트는 백엔드 프롬프트 변환 로직 검증과 웹 UI 시연 환경의 유지보수성을 극대화하기 위해 **관심사 분리(Separation of Concerns)** 원칙에 따라 스크립트를 분리하여 구축했습니다.

| 구분 | `main.py` (CLI 백엔드 검증) | `app.py` (Gradio 웹 UI) |
| :--- | :--- | :--- |
| **핵심 역할** | 행정 보고서체 변환 프롬프트 및 Chain 로직 검증 | `gr.ChatInterface` 기반 인터랙티브 대화 및 피드백 수집 |
| **주요 기능** | - 입력 메모에 대한 개조식 텍스트 변환 출력<br>- CLI 빠르게 변환 품질 테스트 | - 예시 민원 클릭을 통한 즉시 변환 테스트<br>- `flagging_options`로 변환 피드백 수집 및 저장 (`Port 7864`) |
| **추천 활용** | 로직 수정, 프로토타이핑, 디버깅 | 포트폴리오 시연, 발표, 실무자 웹 구동 |
