# 01. 도시정비 민원 및 규정 QA 시스템 (Urban RAG System)

도시 및 주거환경정비법 등 정비사업 관련 법령 및 가이드라인 문서를 벡터화하여, 부칙·시행일자 기반의 정확한 규정 조회 및 답변을 자동화하는 RAG 시스템입니다.

---


## 📌 주요 특징 (Key Features)

1. **자동 문서 로드 및 FAISS Vector DB 구축**
   - `data/` 폴더 내의 PDF 문서(예: 도시 및 주거환경정비법)를 자동 검출하여 텍스트 분할 및 FAISS 인덱스 생성.
2. **부칙 및 시행일자 검증 프롬프트**
   - 질문에 대해 단순 조문 검색뿐만 아니라 법령의 개정 이력, 신설 일자, 시행일자/부칙 내용을 반드시 검증하도록 프롬프트 설계.
3. **할루시네이션(지어내기) 방지**
   - [참고 규정]에 명시되지 않은 내용은 추측하여 답변하지 않고, 정보 부재를 정직하게 명시하도록 제어.

---
## 🎯 1. 프로젝트 목적 (Purpose)

1. **도시정비 법령 질의응답 자동화 및 행정 효율성 제고**
   - 수백 페이지에 달하는 「도시 및 주거환경정비법」 법령 문서를 실시간 탐색하여 민원 응대 시간을 단축.
2. **부칙 및 개정 시행일자 기반의 정확한 규정 검증**
   - 단순 본문 조문 검색을 넘어 법령의 개정 이력, 부칙, 신설 일자를 정밀 검증하는 RAG 파이프라인 구축.
3. **법령 답변의 할루시네이션(지어내기) 방지**
   - 문서 내 존재하지 않는 조항에 대해 거짓 정보를 제공하는 현상을 차단하고 엄격한 근거 중심 답변 출력.

---

## 💡 2. 추진 배경 (Why)

1. **정비사업 관련 법령의 잦은 개정으로 인한 해석 혼선**
   - 도시정비법은 사업시행계획, 관리처분계획 등 단계별로 부칙 및 시행일자에 따라 적용 법조문이 달라져 오적용 위험 존재.
2. **반복적인 지자체·조합 민원 질의로 인한 업무 과중**
   - 정비구역 지정 기본요건, 동의율 계산 기준 등 반복 민원에 대한 신속하고 정밀한 표준 답변 도구 필요.
3. **법률 가이드라인 검색 및 검증 절차의 수동성**
   - 담당자가 매번 법제처 법령집 PDF를 수동으로 검색하는 방식을 개선하여 AI 기반 검색 체계 도입.

---

## ⚠️ 3. 문제점 (Problems Addressed)

1. **일반 LLM의 법률 부칙 및 개정일자 오인 문제**
   - 기본 LLM 모델 사용 시 구 법령과 신 법령의 부칙 시행일자를 구분하지 못해 잘못된 기준을 안내하는 현상 발생.
2. **법령 조문 인용 시 출처 페이지 미제공**
   - 기존 질의응답 시스템에서 답변 근거가 되는 원문 페이지를 확인할 수 없어 정밀성 검증 한계.
3. **PDF 문서 수동 탐색에 따른 과도한 시간 소요**
   - 부칙 및 특례 조항이 복잡하게 얽혀 있어 단순 키워드 검색만으로는 정확한 관련 조문을 찾기 어려움.

---

## 🛠️ 4. 개선안 (Solutions Provided)

1. **부칙/시행일자 필수 검증 프롬프트 및 FAISS Vector DB 구축**
   - 시스템 프롬프트에 부칙 및 개정 일자 검증 수칙을 강제하여 법적 적용 시점을 정밀 파악하도록 제어.
2. **출처 페이지 매핑 및 Gradio UI 제공**
   - 답변 하단에 `📌 참고 출처: Page X, Page Y` 형태로 원문 페이지를 명시하고 `gr.File` 기반 PDF 로더 연동.
3. **Strict Context 기반 답변 체인 구축**
   - [참고 규정]에 밝혀진 내용만을 사용하고, 정보가 없을 경우 정직하게 미기재 사실을 안내하도록 구현.

---

## 🚨 5. 한계점 (Limitations)

1. **변호사·행정사의 최종 법적 해석 대체 불가**
   - 본 AI는 법령 텍스트 기반 조문 검색 보조 도구이며, 실제 소송이나 유권해석의 최종 판단은 법률 전문가의 확인 필요.
2. **스캔본 PDF(이미지형) 텍스트 추출 제약**
   - 텍스트 레이어가 없는 스캔 형태의 PDF 파일 입력 시 OCR 전처리 과정 없이는 정밀 인덱싱 한계.
3. **복수 하위 지침간 유기적 상충 검토 범위 제한**
   - 국토부 상위 법령과 지자체 조례·지침 문서 간의 복잡한 다중 상충 관계는 검색 K값 범위 내 문서로 한정됨.

---

## 🛠️ 6. 실행 스크립트 이원화 설계 (Architecture)

본 프로젝트는 백엔드 핵심 파이프라인 검증과 웹 UI 시연 환경의 유지보수성을 극대화하기 위해 **관심사 분리(Separation of Concerns)** 원칙에 따라 스크립트를 분리하여 구축했습니다.

| 구분 | `main.py` (CLI 백엔드 검증) | `app.py` (Gradio 웹 UI) |
| :--- | :--- | :--- |
| **핵심 역할** | 백엔드 RAG 로직 검증, 터미널 자동화 및 빠른 테스트 | 웹 브라우저 기반 GUI 시연 및 대화형 UI 지원 |
| **주요 기능** | - 콘솔 로그를 통한 빠른 파이프라인 검증<br>- 단일/복수 질문에 대한 입출력 흐름 디버깅 | - PDF 파일 업로드 및 대화 세션 유지<br>- UI 상의 출처(페이지) 매핑 (`Port 7861`) |
| **추천 활용** | 로직 수정, 프로토타이핑, 디버깅 | 포트폴리오 시연, 발표, 실무자 웹 구동 |

---
