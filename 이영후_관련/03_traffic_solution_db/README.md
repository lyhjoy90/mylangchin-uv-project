# 03. 교통 문제 해결 대책 DB 추천 시스템 (Traffic Solution DB)

과거 교통 정체 및 사고 우수 개선 사례 데이터를 벡터화하여, 현장 문제 유형(병목, 딜레마존, 꼬리물기 등)에 상응하는 최적의 개선대책안을 추천하는 AI 컨설팅 솔루션입니다.

---

## 📌 주요 특징 (Key Features)

1. **메타데이터 기반 사례 DB 구축**
   - 위치 유형(`location_type`), 문제 유형(`issue`) 메타데이터를 결합한 FAISS Vector DB 구축.
2. **맞춤형 개선대책 자동 인용**
   - 질의된 현장 상황과 가장 유사한 과거 우수 사례(노면 색상유도선, All-Red 연장, ITS 램프 미터링 등)를 찾아 대책 제시.
3. **Gradio Tabs 기반 AI 추천서 & 원문 DB 이원화 노출**
   - `gr.Tabs`를 적용해 [🤖 AI 종합 추천서] 탭과 [📑 검색된 우수사례 원문 DB] 탭을 분리하여 투명한 인용 근거 제공.

---

## 🎯 1. 프로젝트 목적 (Purpose)

1. **과거 교통 개선 우수사례 DB 활용성 증대**
   - 축적된 교통 정체/사고 개선 우수사례 문서를 벡터 DB화하여 유사 현장 문제 발생 시 즉각적인 벤치마킹 지원.
2. **현장 맞춤형 AI 종합 대책 추천서 생성**
   - 현장의 정체/사고 상황을 입력받아 과거 우수사례에 기반한 종합 개선 대책 보고서를 자동 가공.
3. **투명한 인용 근거 제공 (AI 추천서 vs 원문 DB 이원화)**
   - AI 추천 답변과 실제 참고한 과거 우수사례 원문 DB를 탭으로 분리하여 추천안의 신뢰성 확보.

---

## 💡 2. 추진 배경 (Why)

1. **교통 개선 사업 시 기존 성공 사례 참조의 어려움**
   - 각 지자체나 도로관리청에 분산된 교통 개선 우수사례 데이터가 제대로 공유되지 않아 유사 정체 문제에 대해 매번 중복 연구 수행.
2. **현장 담당자의 교통공학적 대책 수립 전문성 보완**
   - 신호 운영, 노면 색상유도선, All-Red 연장, ITS 램프미터링 등 다양한 공학적 대책 중 현장에 가장 적합한 방안 발굴 체계 필요.
3. **AI 추천안에 대한 현장 적용 검증 문제**
   - AI가 제시한 대책이 실제 성공했던 과거 사례에 근거한 것인지 원문을 직접 비교·검증할 수 있는 인터페이스 요구.

---

## ⚠️ 3. 문제점 (Problems Addressed)

1. **단순 키워드 검색 방식의 과거 사례 탐색 한계**
   - "좌회전 대기행렬 침범"과 같은 복합 현장 상황에 대해 단순 키워드 검색으로는 유사 우수사례 수집 어려움.
2. **AI 대책 제안 시 근거 없는 일반론적 답변 출력**
   - RAG 연동 없이 LLM만 사용 시 현실과 맞지 않거나 검증되지 않은 일반론적인 대책을 제안하는 한계.
3. **단일 화면에서 원문 문서와 요약 답변의 시각적 혼선**
   - AI의 가공된 추천서와 원문 DB 텍스트가 한 화면에 섞여서 출력될 경우 내용 파악이 어렵고 가독성이 떨어짐.

---

## 🛠️ 4. 개선안 (Solutions Provided)

1. **FAISS 기반 Semantic Similarity Search (k=6) 파이프라인 구축**
   - 문제 유형 드롭다운과 상세 설명을 결합한 질의어로 유사도 높은 과거 우수사례 6건을 정밀 추출.
2. **Gradio Tabs 컴포넌트를 활용한 화면 이원화**
   - [🤖 AI 종합 추천서] 탭과 [📑 검색된 우수사례 원문 DB] 탭을 완벽히 분리하여 사용자가 원하는 정보를 명확히 구분 및 비교 검증.
3. **교통공학 컨설턴트 롤플레잉 프롬프트 작성**
   - 추출된 사례 DB를 바탕으로 현장 문제에 바로 적용할 수 있는 공학적 개선 대책 보고서체로 최종 가공.

---

## 🚨 5. 한계점 (Limitations)

1. **미수집 신종 교통 문제 유형에 대한 대책 제한**
   - DB 내에 존재하지 않는 전혀 새로운 교통 패턴(예: UAM 상공 교통 정체 등)에 대해서는 유사 사례 인용 한계.
2. **현장 시뮬레이션(VISSIM 등) 연동 미비**
   - 제안된 대책에 대한 정량적 개선 효과(대기행렬 감소율 등)는 과거 사례 수치를 인용할 뿐 실시간 교통 시뮬레이션 검증은 미포함.
3. **지자체 예산 및 도로 여건 변수 반영 한계**
   - 제안된 대책이 요구하는 설치 예산 규모나 도로 폭원 조건 등의 현실적 제약 요소를 완벽히 고려하기 위해서는 추가 검토 필요.

---

## 🛠️ 6. 실행 스크립트 이원화 설계 (Architecture)

본 프로젝트는 백엔드 DB 검색 엔진 검증과 웹 UI 시연 환경의 유지보수성을 극대화하기 위해 **관심사 분리(Separation of Concerns)** 원칙에 따라 스크립트를 분리하여 구축했습니다.

| 구분 | `main.py` (CLI 백엔드 검증) | `app.py` (Gradio 웹 UI) |
| :--- | :--- | :--- |
| **핵심 역할** | 과거 개선 사례 DB 인덱싱 및 RAG 추천 검증 | 탭(Tab) 분리형 대책 추천 및 원문 DB 비교 시연 UI |
| **주요 기능** | - 정체/사고 현장에 대한 공학적 대책 표 출력<br>- CLI 콘솔 파이프라인 검증 | - 문제 유형 드롭다운 및 현장 설명 입력 폼<br>- AI 추천서와 유사 사례 원문 DB 탭 연동 (`Port 7863`) |
| **추천 활용** | 로직 수정, 프로토타이핑, 디버깅 | 포트폴리오 시연, 발표, 실무자 웹 구동 |
